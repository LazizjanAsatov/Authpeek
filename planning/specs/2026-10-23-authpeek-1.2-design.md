# AuthPeek 1.2 — design

Date: 2026-10-23. Research behind this: `planning/research/2026-10-23-brief.md`.

## Intent

1.1.3 is correct and tested. 1.2 is the version we want people to find, trust and keep:
it should look like a premium product, let people share a code or hand an account to
another device without a server, and be findable in the Chrome Web Store, Google and AI
assistants. Everything stays true to the promise on the front page: no servers, nothing
leaves the browser unencrypted.

## Goals

- Share one code with someone for a few minutes, with no server and no secret exposed.
- Move an account to a phone or another app by QR / `otpauth://` link, from the popup.
- A popup and settings page that read as premium: typography, logos, motion, theme.
- Store listing and site copy that rank for "authenticator", "2FA", "autofill" and get
  cited by AI answers, within Google's listing rules.
- Ship as 1.2.0 with every existing test green, e2e covering the new flows, both zips built.

## Non-goals

- No backend, no accounts, no analytics. No optional "cloud" tier.
- No new Chrome permissions (no `favicon` permission; logos are bundled or monograms).
- No localisation of the extension UI in 1.2 (listing localisation is a later, separate step).
- No counter-based (HOTP) support.

## Anti-goals (would make 1.2 a failure even if it works)

- A share link that sends anything to GitHub or anyone: the key must live only in the URL
  fragment, and the viewer page must work with the network tab empty after load.
- A "premium" look that slows the popup (it must open and show codes as fast as now) or
  breaks the e2e suite's selectors without updating the tests.
- Listing copy that trips the spam rules (keyword stuffing, unattributed trademarks,
  testimonials) or claims ratings/featured status.

## Constraints

- Manifest V3, Chrome >= 127 (set in the 1.1.3 follow-up fix), Firefox build must still lint clean.
- Vault storage format and keys never change (`CHECK_VALUE`, `acct:` items, `meta`).
- Stay in plain ES modules, no bundler. New vendor code must be MIT/OFL/CC0 and kept in
  `extension/vendor/` with its licence file.
- Sync storage item limit 8 KB: nothing new is written to sync except settings.

## Part 1 — Share

### 1a. Share codes (a one-time code for a few minutes)

Entry: a **Share** action on every account (row action and in the edit view). It opens a
`share` view in the popup with two sections: *Share codes* and *Move to another app*.

Flow for *Share codes*:
1. Choose how long: 2, 5 (default) or 10 minutes.
2. AuthPeek computes every code the account will show in that window
   (`ceil(minutes*60 / period)` codes starting at the current step), builds
   `{ v: 1, name, period, digits, start, codes }` and encrypts it with AES-256-GCM under a
   fresh random key (`lib/crypto.js` primitives; no password involved).
3. The link is `https://lazizjanasatov.github.io/Authpeek/share#v1.<ct>.<key>` where both
   parts are base64url. Fragments are never sent to the server (RFC 3986 section 3.5).
4. Buttons: **Copy link**, **Show QR** (for a phone to scan), **Share...** when
   `navigator.share` exists (feature-detected inside the click handler).
5. The viewer `docs/share.html` (static, no network after load) reads `location.hash`,
   decrypts, shows the current code large, a countdown, the next code small, and clear
   "expired" and "this link is damaged" states. It never writes the payload anywhere.
6. The same link pasted into the AuthPeek popup (existing paste handler) opens a
   *Shared codes* view with the same display, for people who have AuthPeek.

Rules: the secret is never in the payload. No revocation (say so in the UI: "Anyone with
the link can see these codes until they expire"). First use shows a short notice; the
privacy policy gains a paragraph. Google's own wording goes next to the button: never
share codes with someone you don't know.

### 1b. Move to another app (the `otpauth://` link)

Section *Move to another app* in the same view: one explicit button **Show QR** reveals a
locally rendered QR of the standard `otpauth://totp/...` link (same text as the settings
page export), plus **Copy link**. A warning line says the link contains the secret key.
Nothing is saved to disk; the QR is drawn into a canvas only while shown.

QR encoding: vendor `qrcode-generator` (MIT, ~25 KB) as `extension/vendor/qrcode.js`.

### Library

`extension/lib/share.js`: pure functions, unit tested with fake time:
`codesForWindow(account, startMs, minutes)`, `encodeShare(payload)` -> `{ fragment }`,
`decodeShare(fragment)` -> payload or throws, `currentCode(payload, nowMs)`,
`isExpired(payload, nowMs)`. `docs/share.html` imports nothing from `extension/`; it has
its own small copy of the decode/display code (plain script) so the Pages site stays
standalone — keep both in sync via a test that runs the decode in both.

## Part 2 — Premium look

Chosen direction: _to be picked from the three mockups in `planning/mockups/`_
(refined / ring / editorial). Whatever is chosen, these hold:

- **Type:** Inter (OFL) bundled as a variable woff2 in `extension/fonts/`, with
  `font-variant-numeric: tabular-nums slashed-zero` on codes. Code digits 22-26 px grouped
  "492 817"; Steam's 5 characters stay one block.
- **Logos:** a curated subset of Simple Icons (CC0) as inline SVG strings in
  `extension/lib/logos.js`, matched by issuer slug and by linked site domain; fallback to the
  existing coloured monogram. Roughly 120 of the services people actually have 2FA on
  (GitHub, Google, Amazon/AWS, Microsoft, Apple, Facebook, Instagram, X, Discord, Steam,
  Dropbox, Slack, Stripe, PayPal, Coinbase, Binance, Cloudflare, Namecheap, GoDaddy, Reddit,
  Twitch, Epic, Nintendo, PlayStation, Shopify, Twilio, DigitalOcean, Heroku, Vercel,
  Netlify, GitLab, Bitbucket, Atlassian, Notion, Figma, LinkedIn, Zoom, Proton, 1Password,
  Bitwarden, LastPass, Okta, ...). Each SVG kept under 2 KB; total well under 300 KB.
- **Theme:** a *Light / Dark / System* setting on the settings page (default System),
  applied via `data-theme` on `<html>` in popup, options and privacy pages.
- **Motion:** 150-180 ms fades for copy/fill confirmation and code roll-over; honour
  `prefers-reduced-motion`.
- **Settings page** restyled to match; a **Rate AuthPeek** link (plain, no incentive) that
  appears only once `STORE_URL` in `lib/config.js` is set.
- **Welcome page** (`welcome.html`) opened once on install: three steps (add an account,
  link a site, that's it) with the GIF. Nice-to-have; last in the plan.

## Part 3 — Findability

- Manifest `name`: `AuthPeek – 2FA Authenticator & Code Autofill` (<= 75).
  `description`: `Authenticator for Chrome: generates 2FA codes and fills them into login
  pages. Encrypted sync across your browsers, no servers.` (<= 132; unit test enforces).
- `docs/store-listing.md`: new description (overview paragraph + short feature list; the
  word "code" under five times; "Google Authenticator(TM)" with attribution line), category
  **Privacy & Security**, the Search Console steps, and the "Rate" link rule.
- `docs/index.html`: title `AuthPeek – Open-source authenticator extension for Chrome that
  autofills 2FA codes`; canonical, Open Graph/Twitter tags with `screenshots/autofill.png`;
  `SoftwareApplication` JSON-LD (no aggregateRating); visible FAQ with one H2 per question
  (syncs? open source? where are the secrets? phone needed? Google Authenticator import?);
  a neutral, factual comparison table (AuthPeek vs Google Authenticator vs Authenticator
  (authenticator.cc) vs Bitwarden) whose every cell is checked against the vendor's own
  page; visible "Last updated - v1.2.0". `docs/robots.txt`, `docs/sitemap.xml`.
  A commented placeholder for the Search Console verification meta tag.
- README: trademark attribution; Rate link later.
- Privacy policy (`extension/privacy.html` = `docs/privacy.html`): share links paragraph;
  bump the date and version line.
